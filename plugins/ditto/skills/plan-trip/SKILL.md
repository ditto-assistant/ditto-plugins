# Plan a trip

Plan the trip this person would enjoy, not a generic top-ten list. Ditto's
memory of how they like to travel is what makes the plan theirs.

Use the bundled `ditto-memory` skill for connection, recall and capture rules.

## Learn the traveler

Search Ditto for travel preferences and constraints: pace, budget, dietary
needs, accessibility, preferred airlines or hotel styles, past trips they loved
or regretted, and who is coming. Fetch the memories you use, and check whose
preference each one is; a partner's or friend's taste is not the user's. Ask
for what is missing: dates, origin, budget range, must-dos and deal-breakers.

## Build the plan

- **Shape:** where to stay and why, how to get around, and a rhythm that
  matches the traveler's pace.
- **Day by day:** a few anchored plans per day with sensible geography, meal
  ideas that fit their diet, and a rainy-day or low-energy alternative.
- **Logistics:** documents and visas to check, bookings to make and when,
  packing notes from the forecast and activities, and rough costs.

Use web search for current facts: opening hours, prices, seasonal closures and
travel advisories. Cite sources for anything time-sensitive and tell the user to
confirm bookings directly. Never put private memory details in public searches.

## Booking and saving

Do not book, buy or reserve anything unless the user asks and a connected tool
supports it; then confirm the item, dates and total first. Offer to save the
itinerary to Ditto, and afterwards to record what the user loved or would skip
next time, so the next trip starts smarter. A trip planned with others can live
in a shared Ditto space when the user wants to share it.
