# Daily brief

A short morning page that answers "what matters today?" from what Ditto already
knows, so the user does not have to reconstruct it.

Use the bundled `ditto-memory` skill for connection, recall and capture rules.

## Build the brief

Search Ditto for what is relevant to today: priorities the user set, deadlines
and commitments due soon, promises made to other people, open loops waiting on
someone, and personal reminders (birthdays, appointments, habits the user is
building). Read a connected calendar or task list when the user has one and
asks you to use it. Fetch the records you rely on and check their dates; a
"due Friday" saved three weeks ago may already be past.

Keep it to one screen:

- **Top three:** the most important outcomes for today, with a first step each.
- **Commitments:** meetings and promises with times and people.
- **Waiting on:** what others owe the user, and when to nudge.
- **Don't forget:** small personal items.

Mark anything inferred. If memory is thin, say so and ask the user for today's
priorities instead of padding the brief.

## End of day (optional)

When the user comes back with a recap, update the records: mark finished items,
carry unfinished ones forward and save new commitments. Save only what the user
confirms.

## Every morning

Offer a Ditto workflow that writes this brief on a schedule the user picks, in
their time zone, delivered where they choose. Create it only on the user's yes;
anything that would send or post on their behalf needs their explicit approval
when the workflow is created.
